# bbTrader_claude

틱 데이터 기반 국내주식 단타 자동매매 시스템. 실시간 체결틱에서 매수세를 읽어 진입하고,
가격 트레일링으로 청산한다. 백테스팅과 실매매가 **동일한 판정 정의**를 공유하며, 그 등가성을 재생으로 검증한다.

---

## 1. 전략 개요

장중을 **두 구간**으로 나누어 서로 다른 로직을 적용한다. 같은 종목에 대해 포지션은 **항상 하나만** 유지한다.

### 구간1 — 개장 09:00~09:10 (흐름추종)

개장초는 기회 밀도가 종일 대비 2~3배이지만, 구간2 로직으로는 **구조적으로 진입할 수 없다**.
당일고가가 아직 형성되지 않아 이격률이 평균 2.8%(요구 5% 미달)이고, 상대지표(거래강도·체결속도)도
개장초에는 기준선 자체가 높아 서지가 검출되지 않는다. 그래서 **절대 기준** 전용 로직으로 분리했다.

| 구분 | 조건 |
|---|---|
| 진입 | 유효 매수 체결 **≥7회/초** (10초 창, 1·2주 제외, 절대 기준)<br>**AND** 단가 상승 (10초 전 대비)<br>**AND** 순매수비율 ≥0.5 (동일 10초 창) |
| 청산 | **트레일링 2.0%** (보유중 고점 대비) |
| 안전장치 | 손절 1.5% · 최대보유 1800초 · 장마감 청산 · **종목당 1일 1회** (쿨다운 180초는 사실상 사문화) |
| 주문 | 매수 IOC 지정가 **현재가 +5호가** (구간2는 +3호가) — 체결 폭증 한복판 진입이라 호가가 빠르게 밀려 미체결 방지 |

> **매수세는 진입 신호로는 좋고 청산 신호로는 나쁘다.** 체결 서지는 직후 바로 꺾이지만 가격 추세는 더 간다.
> 매수세 소멸로 청산하면 평균보유 68초·평균수익 +2.24%인 반면, 트레일링은 347초·+3.35%다.
> (구간2에서 이미 얻은 교훈의 재확인)

> **한 종목에 두 번 들어가지 않는다** (2026-07-28). 재진입 16건을 전수 검증한 결과 1회차 52건이
> 평균 +1.03%인 데 비해 재진입은 평균 −0.84%(4승 12패, 부호검정 p=0.038)였다. 구간1 2회차 7건은
> 2승 5패·합계 −5.38%라 상한을 1로 내렸다(계좌 +14.78% → +16.38%, 7일 중 5일 개선).
> 직전 손익으로 거르는 조건부 규칙은 성립하지 않는다 — **직전이 이익일 때의 재진입이 오히려 더 나빴다**.

### 구간2 — 09:10 이후 (눌림매매)

매수세가 터지되 **당일고가 대비 눌린 자리**에서만 산다. 이 전략의 실질 엣지는 거래량 서지가 아니라
**할인(평균회귀)** 에 있다 — 16개 지표를 백지에서 경쟁시킨 결과 이격률이 예측력 상위이고
거래량 계열은 약했다(리프트 1.1). 거래량 필터는 알파가 아니라 **노이즈 제거** 역할이다.

| 구분 | 조건 |
|---|---|
| 진입 | 순매수비율 >0.6 · 거래강도 >5.0 · 60초 거래량 ≥10,000주<br>· 체결속도 ≥3.5 · 덩어리배수 ≤30 · **이격률 5~14%** |
| 청산 | 트레일링 2.5% · 본전방어 발동 +1.5% |
| 안전장치 | 손절 1.5% · 최대보유 3600초 · 장마감 청산 · 쿨다운 300초 · 종목당 1일 2회 |

### 주문 · 체결 모델

- **매수**: IOC 지정가, 현재가 + N호가(구간1 5 / 구간2 3). 지정가는 상한일 뿐이라 실제로는 최우선 매도호가에 체결된다.
- **매도**: IOC 지정가, **현재가 − 5호가**. 시장가는 호가를 쓸어내려 체결가가 밀린다
  (2026-08-04 재실측: 그 초 실제가 대비 −0.036%, 42건). 지정가 하한을 두면 최우선 매수호가에 체결되어 극단적 미끄러짐만 차단된다.
  단 **장마감 청산은 시장가 유지** — 미체결 시 오버나이트 리스크가 더 크다(`TB_CLOSEMKT=0`으로 해제 가능).
- **백테 체결 모델**: 실측 기반으로 보수화했다(2026-07-28 실전 6건 대조, 괴리 2.94%p → 0.27%p).
  - 청산가는 스탑 레벨이 아니라 **스탑을 터치한 그 초의 실제 가격**을 쓴다 — 터치 시점 가격은 이미 스탑 아래다(모델 낙관 0.13%p 해소)
  - 진입 슬리피지 0.20% / 청산 슬리피지 0.08%를 별도 반영(`TB_BUYSLIP`/`TB_SELLSLIP`)
  - **2026-08-04 재실측 (매수·매도 각 42건 / 9거래일, 주문체결 원장·실시간매매 로그·틱 3중 교차)**

    | 구분 | 완결초 → 주문시점<br>(판정·주문 지연 중 가격이동) | 주문시점 → 체결<br>(호가 슬리피지) | 실측 합계 | 부트스트랩 95% | 가정 |
    |---|---|---|---|---|---|
    | 매수 | +0.161%p | +0.021%p | **+0.183%** | [+0.076, +0.314] | 0.20% (유지) |
    | 매도 | +0.027%p | +0.009%p | **+0.036%** | [−0.075, +0.137] | 0.15% → **0.08%** |

    - **IOC 지정가 주문 자체는 사실상 공짜다.** 매수 체결가가 최우선매도호가와 같은 경우 37/42건,
      주문가격보다 싸게 체결 40/42건 — +3/+5호가를 얹어도 실제론 최우선호가에서 체결된다.
      비용의 대부분은 호가가 아니라 **판정에서 주문까지의 지연 중 가격이동**이고, 매수는 상승 국면이라
      체계적으로 불리하지만 매도는 방향성이 없어 거의 0이다. 매도 IOC 지정가 전환이 매도 슬리피지를 실질적으로 없앴다.
    - 매도를 점추정치 0.036 이 아니라 **0.08 로 둔 이유**: 표본 42건이라 값이 아직 흔들리고,
      낮추는 방향은 백테를 낙관 쪽으로 미는 방향이라 보수적으로 잡는다. 표본이 쌓이면 재조정한다.
    - **이건 전략이 좋아진 게 아니라 백테가 실제를 과소평가하고 있었다는 뜻이다.** 실매매 성과는 이미
      실측값대로 나오고 있었다 — 바뀌는 것은 백테 숫자뿐이고, 과거 홀드아웃 누적치도 소급해 달라진다.

### 종목선정 — 두 단계

전체 시장에서 매매할 종목을 고르는 일은 **성격이 다른 두 단계**로 나뉘어 있다.
1단계는 **무엇을 볼 것인가**(틱을 수신할 100종목)를 정하고, 2단계는 그 100종목 중 **무엇을 살 것인가**를 정한다.
단계마다 실행 주체·시점·기준이 다르다.

| | 1단계 | 2단계 |
|---|---|---|
| 산출물 이름 | **감시종목** (100개 고정) | **매매대상** (14~44개, 변동) |
| 하는 일 | 실시간 체결틱 수신 등록 | 구간1·구간2 진입 판정 |
| 실행 시점 | 매일 장 시작 전 1회 | 장 시작 전 1회 (1단계 직후) |
| 실행 위치 | `trader/bot_실시간수신.py` `make_감시종목()` | 실시간 `bot_실시간매매.py` `set_매매대상선정()`<br>백테 `bot_백테스팅_틱기반매수세.py` `pick_종목선정()` |
| 판단 기준 | 추세(정배열) + 관심도 + 거래대금 | 유동성·가격 하한만 |

**용어 주의.** `매매대상`은 **2단계 산출물만** 가리킨다. 1단계 산출물인 감시종목 파일 안에도 두 개의 키가 있지만
그것은 100종목을 조회순위 포함 여부로 나눈 분류일 뿐, 매매 여부와 무관하다.
(구 키명 `매매대상`/`수집대상`이 매매 유니버스로 오해되어 2026-08-03에 `조회순위포함`/`조회순위미포함`으로 개명했다. 과거 파일도 전부 변환됨)

---

#### 1단계 — 전체 시장(약 4,430종목) → 감시종목 100개

**시장 전체에서 "오늘 급등이 나올 만한" 100개를 미리 추려두는 단계**다.
실시간 체결틱은 미리 등록한 종목만 수신되므로, 여기서 빠진 종목은 그날 매매도 사후 분석도 불가능하다.
100이라는 수는 `make_감시종목()`의 `[:100]`으로 정해진 현재 설정값이다.
전날 장 마감 후 확정된 **전일 일봉**만 쓴다. 당일 정보는 일절 쓰지 않는다.

**입력 세 가지** (모두 전일 기준)

| 입력 | 내용 | 규모 |
|---|---|---|
| 전일 일봉 캐시 | 이동평균·거래대금이 계산된 전 종목 일봉 | 4,423~4,432종목 |
| 조건검색 「분석대상종목」 | 관리종목·우선주 등을 걷어낸 매매 가능 모집단 | 2,403~2,446종목 |
| 빅데이터 조회순위 | 키움 조회순위 상위 (투자자 관심도) | 73~108종목 |

**플래그 세 개**를 전 종목에 붙인다.

| 플래그 | 뜻 |
|---|---|
| `거래대상포함` | 조건검색 「분석대상종목」에 있는가 |
| `조회순위포함` | 빅데이터 조회순위에 있는가 |
| `정배열` | 전일 종가 기준 5일선 > 20일선 > 120일선 |

**정렬해서 위에서 100개를 자른다.**
정렬키는 `거래대상포함` → `정배열` → `조회순위포함` → `거래대금(백만)` 순이고 전부 내림차순이다.
앞의 셋은 참/거짓이므로 이 정렬은 사실상 **우선순위 계층**을 만든다 — 세 조건을 다 만족하는 무리가 먼저 들어가고,
같은 계층 안에서는 **전일 거래대금이 큰 종목이 앞선다.**

| 순위 | 계층 | 실측 규모 | 100칸 배정 |
|---|---|---|---|
| 1 | 분석대상 ∩ 정배열 ∩ 조회순위 | 3~13종목 | **전부 채택** |
| 2 | 분석대상 ∩ 정배열 (조회순위 없음) | 116~183종목 | 거래대금 순으로 **남은 칸을 채우고 잘림** |
| 3 이하 | 정배열이 아니거나 분석대상이 아닌 종목 | 나머지 전부 | **한 번도 닿지 않음** |

1·2계층 합이 121~195종목으로 항상 100보다 많아서, **감시 100종목은 매일 전부 「분석대상 ∩ 정배열」로 채워진다.**
바꿔 말하면 정배열이 실질적인 진입 관문이고, 거래대금은 그 안에서의 줄 세우기다.

결과는 조회순위 포함 여부로 나눠 `dic_감시종목_YYYYMMDD.pkl`에 두 키로 저장한다 —
`조회순위포함`(3~13종목) / `조회순위미포함`(87~97종목). **두 키를 합친 100종목 전부가 틱 수신 대상이다.**

---

#### 2단계 — 감시종목 100개 → 매매대상 14~44개

1단계가 추세를 이미 걸렀으므로, 여기서는 **거래가 실제로 가능한지만** 본다. 추세·패턴 조건은 없다.

| 필터 | 기준 | 상수 |
|---|---|---|
| 유동성 | 전일 거래대금 ≥ 50억 | `TB_MINVALUE` |
| 가격 | 전일 종가 ≥ 1,000원 | `TB_MINPRICE` |

두 키를 합친 100종목에 이 필터를 걸어 통과한 종목만 구간1·구간2 진입 판정을 받는다.
실측 13일 기준 **14~44종목**이며, 가격 하한은 실제로는 한 종목도 추가로 걸러내지 않았다(거래대금 50억을 넘는 종목은 이미 1,000원을 넘는다).
**실시간매매와 백테스팅이 같은 필터·같은 상수를 쓴다** — 이 등가가 깨지면 백테스트 결과를 신뢰할 수 없다.

유동성 필터는 단순한 위생 조건이 아니라 **알파 방어선**이다.
6일×100종목 전수 재생에서 탈락군 13건은 합계 **−3.44%**였고, 12일 전수 재생에서도
필터를 풀어 100종목 전체로 확대하면 구간1은 4건 0승4패(**−7.91%**), 구간2는 27건 승률 22%(**−27.15%**)로 전부 손실이었다.

---

#### 두 단계를 관통하는 실측

**100칸은 병목이 아니다.** 12일 실측상 시장 전체의 「분석대상 ∩ 정배열 ∩ 거래대금 50억↑」 종목 수와
감시 100개 안의 그 종목 수가 매일 정확히 일치했다. 1계층이 정배열로만 차고 거래대금 정렬 덕에 굵은 종목이 항상 먼저 들어오기 때문이다.
즉 **매매대상 수 = 시장에 그 조건을 만족하는 종목이 몇 개나 있는가**로 결정된다.

| 단계 | 20260716 | 20260731 | 20260803 |
|---|---|---|---|
| 분석대상 ∩ 정배열 | 178 | 121 | 123 |
| 감시종목 | 100 | 100 | 100 |
| 매매대상 | 40 | 14 | 16 |

매매대상이 40개에서 14개로 줄어든 것은 필터나 100칸 제한 탓이 아니라 **조건을 만족하는 종목이 시장에서 줄었기 때문**이다.

**정배열 완화는 검증 불가라 보류 중이다.** 1단계 조건을 5일선 > 120일선으로만 완화하면 후보가 337~410종목으로 두 배가 되고
매매대상도 58~100개로 늘지만(현행 매매대상은 거의 그대로 유지되고 순증), 새로 들어오는 종목의 80%가 5일선 < 20일선 영역이다.
현행 표본에서 이 이격이 좁을수록 거래발생률·평균수익·승률이 단조로 나빠지고 가장 낮은 칸(1.00~1.02)은 5건 −2.72%다.
무엇보다 **감시 100종목 외에는 틱이 없어 백테스트 자체가 불가능하다.** (2026-08-03 검토)

  구간2는 3분할이 위험 대비 수익의 정점이다(그보다 공격적이면 먼저 온 거래가 자본을 소진해 수익은 안 늘고 위험만 커진다).
  구간1만 4분할인 이유는 **09:00~09:10에 신호가 몰리고 평균 보유가 347초라 서로 겹치기 때문**이다 —
  자본 무관 최대 동시보유가 4종목인데 3분할이면 4번째가 잔돈으로만 체결된다
  (실측: 07/20 기가레인 목표 337만원 → 실제 4.9만원(1%), 07/23 한울반도체 404만원 → 11.8만원(3%). 둘 다 큰 승자였다).
  5분할 이상은 자본이 놀아 오히려 손해다.

## 3. 실행

### 최초 설정 — `xconfig/`

**손으로 채워야 하는 파일은 전부 `xconfig/` 한 곳에 모여 있다.** 실제 값은 저장소에 올리지 않으므로
(`.gitignore`) 양식만 `.example` 로 올려두었다. 확장자를 떼어 복사한 뒤 실제 값을 채운다.

```bash
cd xconfig && for f in *.example; do cp -n "$f" "${f%.example}"; done
```

| 파일 | 내용 |
|---|---|
| `xconfig/config.json` | 경로·운영 설정. `folder_work` 등 mac/win 경로를 자기 환경에 맞게 고친다 |
| `xconfig/kiwoomKey.json` | 키움 오픈API 앱키·시크릿키. **최상위 키는 계좌번호**이며 `config.json` 의 `계좌번호` 와 일치해야 한다 |
| `xconfig/server_info.json` | 백업·차트 업로드용 sftp 접속정보와 서버 폴더 경로 |
| `xconfig/telegram.json` | 텔레그램 알림봇 토큰·수신 `chat_id`. 쓰지 않으면 파일을 두지 않아도 된다 |

설정폴더 경로는 `ToolManager.folder_설정` 이 잡아 `config로딩()` 결과에 `folder_설정` 키로 주입한다.
설정파일을 새로 추가한다면 이 키를 기준으로 읽어야 위치가 한 곳에 유지된다.

> `xapi/kiwoomToken.json` · `.lock` 은 앱키로 발급받아 캐싱하는 **자동생성물**이라 `xconfig/` 가 아니라
> `xapi/` 에 그대로 둔다. 손댈 일이 없고, 지워도 다음 구동 때 다시 만들어진다.

### 텔레그램 알림 — `xapi/API_telegram.py`

설정은 `xconfig/telegram.json` 두 줄이 전부다.

```json
{
    "bot_token": "BotFather 에서 /newbot 으로 발급받은 토큰",
    "chat_id": "알림 받을 대화 id"
}
```

| 항목 | 뜻 |
|---|---|
| `bot_token` | BotFather 발급 토큰. 비어 있으면 모든 발송이 조용히 무시된다 |
| `chat_id` | 수신 대상. 개인 대화는 양수, 그룹·채널은 `-100` 으로 시작하는 음수 |
| `사용여부` | (선택, 기본 `true`) `false` 면 발송을 전부 건너뛴다 |
| `타임아웃(초)` | (선택, 기본 `10`) 장중 매매 루프가 알림 때문에 멈추지 않게 하는 안전장치 |
| `무음발송` | (선택, 기본 `false`) 알림음 없이 보낼지 |

`chat_id` 는 눈에 보이지 않으므로 **봇에게 아무 메세지나 한 번 보낸 뒤** 아래를 실행한다.

```bash
python xapi/API_telegram.py
```

토큰 유효성(`getMe`)과 설정된 `chat_id` 가 실제로 닿는지(`getChat`)를 확인하고,
닿지 않으면 대화 목록에서 찾아 **설정파일에 자동으로 써 넣는다**
(개인 대화가 하나일 때만 자동 저장하고, 여럿이면 목록만 보여준다. `bot_token` 은 건드리지 않는다).
인자를 주면 시험 발송까지 한다 — `python xapi/API_telegram.py 연결 확인`

> **그룹·채널로 받으려면 봇을 먼저 그 방에 넣어야 한다.** `-100...` 형태의 id 를 넣어도
> 봇이 멤버가 아니면 `chat not found` 로 실패한다. 채널은 봇을 **관리자**로 올려야 하고,
> 그룹은 멤버로 추가하기만 하면 된다. 봇은 자기가 속하지 않은 방의 id 를 조회할 수 없다.

사용은 카카오 모듈과 시그니처를 맞춰 놓아 같은 자리에 끼울 수 있다.

```python
from xapi import API_telegram
tg = API_telegram.TelegramAPI(make_로그=self.make_로그)
tg.send_메세지(s_메세지='[20260803] 백테스팅 완료', s_버튼이름='리포트', s_연결url='http://...')
tg.send_문서(path_파일='...svg', s_설명='매매일보')
```

**알림은 매매의 부수 기능이므로 어떤 경우에도 호출자를 죽이지 않는다.** 설정파일이 없거나 `b_사용` 이 꺼져 있으면
조용히 `False` 를 돌려주고, 통신 오류·API 거부는 전부 내부에서 잡아 로그만 남긴다. 토큰은 로그에 찍지 않는다.
본문이 4,096자를 넘으면 줄 단위로 나눠 보내고 버튼은 마지막 건에 붙인다.

### 진척 대시보드 — `analyzer/대시보드.py`

성능·안정성·목표대비 진척을 한 장으로 보여주는 HTML을 만들어 분석결과 폴더에 저장하고
텔레그램으로 링크를 보낸다. **매일 백테스팅 직후 런처가 자동 실행**한다.

```bash
python analyzer/대시보드.py            # 생성 + 텔레그램 발송
```
```bash
python analyzer/대시보드.py --no-send   # 생성만
```

| 구획 | 내용 |
|---|---|
| 한눈에 | 카드 8장 — 윗줄은 **누적**(백테 계좌 / 홀드아웃 계좌 / 홀드아웃 거래손익 합 / 1차 판정선까지), 아랫줄은 **당일**(계좌 / 거래손익 합 / 거래 수·승패 / 구간별) |
| 진척 | 도넛 4개 — 홀드아웃 15일 / 1차 판정선 90건 / 2차 판정선 180건 / 롤링 재검증 37거래일(10일창 + 27폴드) |
| 성능 | 개발표본 vs 홀드아웃, 구간1·구간2 분해, 최근 10거래일 |
| 안정성 | 손실일 비율, 최대낙폭, 하루빼기 최악, 팻테일 의존도, t값, 실매매 실현손익 |
| 앞으로 | 최근 거래속도로 환산한 남은 거래일과 예상 도달일 |

판정선 근거는 관측 분포(거래당 평균 +0.64%, 표준편차 3.13%, 왜도 1.46) 부트스트랩이다 —
양측 95%·검정력 80%로 "거래당 기대값이 0보다 크다"를 말하려면 참 기대값 +0.90% 가정 시 **90건**,
+0.64% 가정 시 **180건**이 필요하다. **거래 빈도가 국면에 따라 3배 넘게 변하므로
날짜가 아니라 건수로 판단한다.**

**거래손익 합과 계좌 수익률은 다르다.** 진입 한 건에 총자본의 `1/분할수`만 넣으므로 거래 수익률을 단순히
더한 값은 계좌에 그대로 반영되지 않는다(대신 잔고에 복리로 쌓인다). 사이징이 총자본 비례라 수익률은
자본 규모와 무관하므로, **홀드아웃 시작 시점 잔고를 1,000만원으로 환산한 값**을 별도 카드로 보여준다.

설계상 지켜야 할 것:

- **읽기 전용.** `30_거래내역`·`40_결과정리`·주문체결 원장을 읽기만 하고 백테 산출물을 만들거나 고치지 않는다.
- **실패해도 예외를 밖으로 던지지 않는다.** 런처의 다음 작업(`ut_파일정리`)을 막지 않기 위해서다.
  실패하면 로그를 남기고 텔레그램으로만 알린다.
- **카카오에는 일절 관여하지 않는다.** 매매일보 카카오 발송 코드와 시점은 그대로다.
- 저장 폴더·웹 주소는 `xconfig/server_info.json`의 `folder.server_kakao`·`sftp.hostname`에서 유도한다
  (코드에 주소를 박지 않는다).

## 4. 파라미터

전부 모듈 상단 `_T_*` / `_G1_*` 상수이며 **환경변수로 덮어쓸 수 있다**. 백테스팅과 실매매가 같은 이름·같은 기본값을 쓴다.

| 환경변수 | 기본 | 의미 |
|---|---|---|
| `TB_G1` | `1` | **구간1 킬스위치** — `0`이면 구간1 완전 비활성(기존 동작 정확히 복원) |
| `TB_G1RATE` | `7.0` | 구간1 진입: 초당 매수 체결 횟수 하한 |
| `TB_G1RATIO` | `0.5` | 구간1 진입: 순매수비율 하한 |
| `TB_G1TRAIL` | `2.0` | 구간1 트레일링 % |
| `TB_G1END` | `600` | 구간1 종료 (09:00 기준 초) |
| `TB_G1TICKUP` | `5` | 구간1 매수 지정가 = 현재가 + N호가 (구간2는 `TB_TICKUP`=3) |
| `TB_G1MAX` / `TB_MAXPERDAY` | `1` / `2` | 종목당 1일 최대 진입 횟수 (구간1 / 구간2) |
| `TB_G1COOL` / `TB_COOLDOWN` | `180` / `300` | 청산 후 재진입 대기 초 (구간1 / 구간2) — 아래 주 참조 |
| `TB_RATIO` / `TB_INT` | `0.6` / `5.0` | 구간2 진입: 순매수비율 / 거래강도 |
| `TB_DIST` / `TB_DISTMAX` | `5.0` / `14` | 구간2 진입: 이격률 하한 / 상한 |
| `TB_STOP` / `TB_TRAIL` | `1.5` / `2.5` | 손절 % / 구간2 트레일링 % |
| `TB_TICKDN` | `5` | 매도 지정가 = 현재가 − N호가 |
| `TB_CLOSEMKT` | `1` | 장마감 청산만 시장가 유지 (`0`이면 마감도 지정가) |
| `TB_BUYSLIP` / `TB_SELLSLIP` | `0.20` / `0.08` | 백테 진입/청산 체결 슬리피지 % (실측 반영, 매도는 2026-08-04 재보정) |
| `TB_COST` | `0.35` | 왕복 거래비용 % (수수료+세금) |
| `TB_DIVISOR` | `3` | 구간2 총자산 균등 분할 수 |
| `TB_G1DIVISOR` | `4` | 구간1 총자산 균등 분할 수 |
| `TB_DEBUG` | – | 진입조건 추적할 종목코드 (콤마 구분) |

> **쿨다운은 튜닝 대상이 아니다** (2026-07-28 전수 검증). 현행 설정에서 실제 재진입은 구간1이 청산 후
> 중앙값 291초(쿨다운 180의 1.6배), 구간2가 5,216초(300의 17배)에 일어난다 — **쿨다운 경계에 걸려
> 지연된 진입이 한 건도 없다**. 소폭 조정은 거래가 1건도 안 바뀌고, 크게 줄이면(구간1 0초) 재진입이
> 7→15건으로 늘면서 4승 11패·−9.18%, 손실일이 1일 → 2일이 된다. 손절 직후 같은 자리에 다시 들어가
> 16·23·39초 만에 또 털리는 churn이다. 구간2는 0~300초 결과가 동일해 **줄일 여지 자체가 없다**.
> 구간1은 `TB_G1MAX=1`이라 쿨다운이 발동할 일이 없다(0~300초 전부 동일 결과).

## 6. 개발 원칙

이 프로젝트는 과적합으로 여러 번 손실을 본 이력이 있다. 그래서 다음을 규칙으로 삼는다.

1. **표본 외로만 판단한다.** 과거 데이터에 맞춰 파라미터를 고르면 학습셋은 +60%대로 예뻐지지만
   다음 날 성적은 무너진다(검증됨: 튜닝 −12% vs 현행 유지 +9.5%). `워크포워드검증.py`로 확인한 뒤 반영한다.
2. **충실도 게이트를 먼저 통과시킨다.** 검증 도구는 현행 파라미터로 기존 백테 결과를 거래 단위까지
   재현해야 하며, 실패하면 최적화 결과를 아예 출력하지 않는다.
3. **실매매와 백테의 등가를 재생으로 증명한다.** 실제 틱을 실매매 판정 코드에 흘려 넣어
   백테와 진입·청산 시각이 일치하는지 확인한다. (과거에 미배포 코드로 미진입한 장애가 있었다)
4. **하루치 사례로 규칙을 바꾸지 않는다.** 그것이 과적합의 정의다.
5. **새 로직은 킬스위치와 함께 넣는다.**
