# bbTrader_claude

틱 데이터 기반 국내주식 단타 자동매매 시스템. 실시간 체결틱에서 매수세를 읽어 진입하고,
가격 트레일링으로 청산한다. 백테스팅과 실매매가 **동일한 판정 정의**를 공유하며, 그 등가성을 재생으로 검증한다.

---

## 1. 전략 개요

장중을 **두 구간**으로 나누어 서로 다른 로직을 적용한다. 같은 종목에 대해 포지션은 **항상 하나만** 유지한다.

### 구간1 — 개장 09:00~09:10 (흐름추종)

개장초는 기회 밀도가 종일 대비 2~3배이지만, 구간2 로직으로는 **구조적으로 진입할 수 없다**.
당일고가가 아직 형성되지 않아 이격률이 평균 2.8%(요구 5% 미달)이고, 상대지표(거래강도·체결속도)도
개장초에는 기준선 자체가 높아 서지가 검출되지 않는다. 그래서 **절대 기준** 전용 로직으로 분리했다.

| 구분 | 조건 |
|---|---|
| 진입 | 유효 매수 체결 **≥7회/초** (10초 창, 1·2주 제외, 절대 기준)<br>**AND** 단가 상승 (10초 전 대비)<br>**AND** 순매수비율 ≥0.5 (동일 10초 창) |
| 청산 | **트레일링 2.0%** (보유중 고점 대비) |
| 안전장치 | 손절 1.5% · 최대보유 1800초 · 장마감 청산 · **종목당 1일 1회** (쿨다운 180초는 사실상 사문화) |
| 주문 | 매수 IOC 지정가 **현재가 +5호가** (구간2는 +3호가) — 체결 폭증 한복판 진입이라 호가가 빠르게 밀려 미체결 방지 |

> **매수세는 진입 신호로는 좋고 청산 신호로는 나쁘다.** 체결 서지는 직후 바로 꺾이지만 가격 추세는 더 간다.
> 매수세 소멸로 청산하면 평균보유 68초·평균수익 +2.24%인 반면, 트레일링은 347초·+3.35%다.
> (구간2에서 이미 얻은 교훈의 재확인)

> **한 종목에 두 번 들어가지 않는다** (2026-07-28). 재진입 16건을 전수 검증한 결과 1회차 52건이
> 평균 +1.03%인 데 비해 재진입은 평균 −0.84%(4승 12패, 부호검정 p=0.038)였다. 구간1 2회차 7건은
> 2승 5패·합계 −5.38%라 상한을 1로 내렸다(계좌 +14.78% → +16.38%, 7일 중 5일 개선).
> 직전 손익으로 거르는 조건부 규칙은 성립하지 않는다 — **직전이 이익일 때의 재진입이 오히려 더 나빴다**.

### 구간2 — 09:10 이후 (눌림매매)

매수세가 터지되 **당일고가 대비 눌린 자리**에서만 산다. 이 전략의 실질 엣지는 거래량 서지가 아니라
**할인(평균회귀)** 에 있다 — 16개 지표를 백지에서 경쟁시킨 결과 이격률이 예측력 상위이고
거래량 계열은 약했다(리프트 1.1). 거래량 필터는 알파가 아니라 **노이즈 제거** 역할이다.

| 구분 | 조건 |
|---|---|
| 진입 | 순매수비율 >0.6 · 거래강도 >5.0 · 60초 거래량 ≥10,000주<br>· 체결속도 ≥3.5 · 덩어리배수 ≤30 · **이격률 5~14%** |
| 청산 | 트레일링 2.5% · 본전방어 발동 +1.5% |
| 안전장치 | 손절 1.5% · 최대보유 3600초 · 장마감 청산 · 쿨다운 300초 · 종목당 1일 2회 |

### 주문 · 체결 모델

- **매수**: IOC 지정가, 현재가 + N호가(구간1 5 / 구간2 3). 지정가는 상한일 뿐이라 실제로는 최우선 매도호가에 체결된다.
- **매도**: IOC 지정가, **현재가 − 5호가**. 시장가는 호가를 쓸어내려 체결가가 밀린다
  (2026-07-28 실측: 그 초 실제가 대비 −0.15%). 지정가 하한을 두면 최우선 매수호가에 체결되어 극단적 미끄러짐만 차단된다.
  단 **장마감 청산은 시장가 유지** — 미체결 시 오버나이트 리스크가 더 크다(`TB_CLOSEMKT=0`으로 해제 가능).
- **백테 체결 모델**: 실측 기반으로 보수화했다(2026-07-28 실전 6건 대조, 괴리 2.94%p → 0.27%p).
  - 청산가는 스탑 레벨이 아니라 **스탑을 터치한 그 초의 실제 가격**을 쓴다 — 터치 시점 가격은 이미 스탑 아래다(모델 낙관 0.13%p 해소)
  - 진입 슬리피지 0.20% / 청산 슬리피지 0.15%를 별도 반영(`TB_BUYSLIP`/`TB_SELLSLIP`)
  - ※ 실측 표본이 6건이고 매도 주문을 시장가 → 지정가로 바꿨으므로 **며칠 더 모아 재보정 필요**

### 종목선정 · 자금관리

- **종목선정**: 감시종목 중 전일 거래대금 ≥50억, 전일 종가 ≥1,000원.
  유동성 필터는 알파 방어선이다 — 6일×100종목 전수 재생에서 탈락군 13건은 합계 **−3.44%**였다.
- **사이징**: 총자산 균등 분할 — **구간1은 4분할 / 구간2는 3분할**, 거래당 리스크캡 총자본 1.0%.
  구간2는 3분할이 위험 대비 수익의 정점이다(그보다 공격적이면 먼저 온 거래가 자본을 소진해 수익은 안 늘고 위험만 커진다).
  구간1만 4분할인 이유는 **09:00~09:10에 신호가 몰리고 평균 보유가 347초라 서로 겹치기 때문**이다 —
  자본 무관 최대 동시보유가 4종목인데 3분할이면 4번째가 잔돈으로만 체결된다
  (실측: 07/20 기가레인 목표 337만원 → 실제 4.9만원(1%), 07/23 한울반도체 404만원 → 11.8만원(3%). 둘 다 큰 승자였다).
  5분할 이상은 자본이 놀아 오히려 손해다.

## 3. 실행

### 최초 설정 — `xconfig/`

**손으로 채워야 하는 파일은 전부 `xconfig/` 한 곳에 모여 있다.** 실제 값은 저장소에 올리지 않으므로
(`.gitignore`) 양식만 `.example` 로 올려두었다. 확장자를 떼어 복사한 뒤 실제 값을 채운다.

```bash
cd xconfig && for f in *.example; do cp -n "$f" "${f%.example}"; done
```

| 파일 | 내용 |
|---|---|
| `xconfig/config.json` | 경로·운영 설정. `folder_work` 등 mac/win 경로를 자기 환경에 맞게 고친다 |
| `xconfig/kiwoomKey.json` | 키움 오픈API 앱키·시크릿키. **최상위 키는 계좌번호**이며 `config.json` 의 `계좌번호` 와 일치해야 한다 |
| `xconfig/server_info.json` | 백업·차트 업로드용 sftp 접속정보와 서버 폴더 경로 |

설정폴더 경로는 `ToolManager.folder_설정` 이 잡아 `config로딩()` 결과에 `folder_설정` 키로 주입한다.
설정파일을 새로 추가한다면 이 키를 기준으로 읽어야 위치가 한 곳에 유지된다.

> `xapi/kiwoomToken.json` · `.lock` 은 앱키로 발급받아 캐싱하는 **자동생성물**이라 `xconfig/` 가 아니라
> `xapi/` 에 그대로 둔다. 손댈 일이 없고, 지워도 다음 구동 때 다시 만들어진다.

### 구동

```bash
python launcher_trader.py      # 장중 실매매 (08:58 기동)
```
```bash
python launcher_analyzer.py    # 장 종료 후 분석
```

백테스팅 파이프라인은 `pick_종목선정 → make_매매정보 → make_거래내역 → make_결과정리 → make_매매일보`
순서로 돌며, **이미 처리한 일자는 건너뛴다**. 로직을 바꾼 뒤 과거분에 소급 적용하려면
`20_매매정보` 이하 산출물을 지우고 재실행해야 한다.

### 검증 도구

```bash
python analyzer/구간1검증.py       # 구간1 홀드아웃 성적 누적 (신규 일자만 자동 평가)
```

## 4. 파라미터

전부 모듈 상단 `_T_*` / `_G1_*` 상수이며 **환경변수로 덮어쓸 수 있다**. 백테스팅과 실매매가 같은 이름·같은 기본값을 쓴다.

| 환경변수 | 기본 | 의미 |
|---|---|---|
| `TB_G1` | `1` | **구간1 킬스위치** — `0`이면 구간1 완전 비활성(기존 동작 정확히 복원) |
| `TB_G1RATE` | `7.0` | 구간1 진입: 초당 매수 체결 횟수 하한 |
| `TB_G1RATIO` | `0.5` | 구간1 진입: 순매수비율 하한 |
| `TB_G1TRAIL` | `2.0` | 구간1 트레일링 % |
| `TB_G1END` | `600` | 구간1 종료 (09:00 기준 초) |
| `TB_G1TICKUP` | `5` | 구간1 매수 지정가 = 현재가 + N호가 (구간2는 `TB_TICKUP`=3) |
| `TB_G1MAX` / `TB_MAXPERDAY` | `1` / `2` | 종목당 1일 최대 진입 횟수 (구간1 / 구간2) |
| `TB_G1COOL` / `TB_COOLDOWN` | `180` / `300` | 청산 후 재진입 대기 초 (구간1 / 구간2) — 아래 주 참조 |
| `TB_RATIO` / `TB_INT` | `0.6` / `5.0` | 구간2 진입: 순매수비율 / 거래강도 |
| `TB_DIST` / `TB_DISTMAX` | `5.0` / `14` | 구간2 진입: 이격률 하한 / 상한 |
| `TB_STOP` / `TB_TRAIL` | `1.5` / `2.5` | 손절 % / 구간2 트레일링 % |
| `TB_TICKDN` | `5` | 매도 지정가 = 현재가 − N호가 |
| `TB_CLOSEMKT` | `1` | 장마감 청산만 시장가 유지 (`0`이면 마감도 지정가) |
| `TB_BUYSLIP` / `TB_SELLSLIP` | `0.20` / `0.15` | 백테 진입/청산 체결 슬리피지 % (실측 반영) |
| `TB_COST` | `0.35` | 왕복 거래비용 % (수수료+세금) |
| `TB_DIVISOR` | `3` | 구간2 총자산 균등 분할 수 |
| `TB_G1DIVISOR` | `4` | 구간1 총자산 균등 분할 수 |
| `TB_DEBUG` | – | 진입조건 추적할 종목코드 (콤마 구분) |

> **쿨다운은 튜닝 대상이 아니다** (2026-07-28 전수 검증). 현행 설정에서 실제 재진입은 구간1이 청산 후
> 중앙값 291초(쿨다운 180의 1.6배), 구간2가 5,216초(300의 17배)에 일어난다 — **쿨다운 경계에 걸려
> 지연된 진입이 한 건도 없다**. 소폭 조정은 거래가 1건도 안 바뀌고, 크게 줄이면(구간1 0초) 재진입이
> 7→15건으로 늘면서 4승 11패·−9.18%, 손실일이 1일 → 2일이 된다. 손절 직후 같은 자리에 다시 들어가
> 16·23·39초 만에 또 털리는 churn이다. 구간2는 0~300초 결과가 동일해 **줄일 여지 자체가 없다**.
> 구간1은 `TB_G1MAX=1`이라 쿨다운이 발동할 일이 없다(0~300초 전부 동일 결과).

## 6. 개발 원칙

이 프로젝트는 과적합으로 여러 번 손실을 본 이력이 있다. 그래서 다음을 규칙으로 삼는다.

1. **표본 외로만 판단한다.** 과거 데이터에 맞춰 파라미터를 고르면 학습셋은 +60%대로 예뻐지지만
   다음 날 성적은 무너진다(검증됨: 튜닝 −12% vs 현행 유지 +9.5%). `워크포워드검증.py`로 확인한 뒤 반영한다.
2. **충실도 게이트를 먼저 통과시킨다.** 검증 도구는 현행 파라미터로 기존 백테 결과를 거래 단위까지
   재현해야 하며, 실패하면 최적화 결과를 아예 출력하지 않는다.
3. **실매매와 백테의 등가를 재생으로 증명한다.** 실제 틱을 실매매 판정 코드에 흘려 넣어
   백테와 진입·청산 시각이 일치하는지 확인한다. (과거에 미배포 코드로 미진입한 장애가 있었다)
4. **하루치 사례로 규칙을 바꾸지 않는다.** 그것이 과적합의 정의다.
5. **새 로직은 킬스위치와 함께 넣는다.**
