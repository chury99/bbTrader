# bbTrader_claude

틱 데이터 기반 국내주식 단타 자동매매 시스템. 실시간 체결틱에서 매수세를 읽어 진입하고,
가격 트레일링으로 청산한다. 백테스팅과 실매매가 **동일한 판정 정의**를 공유하며, 그 등가성을 재생으로 검증한다.

> 상세 작업 이력·의사결정 근거는 [`_인수인계.md`](_인수인계.md) 참조.

---

## 1. 전략 개요

장중을 **두 구간**으로 나누어 서로 다른 로직을 적용한다. 같은 종목에 대해 포지션은 **항상 하나만** 유지한다.

### 구간1 — 개장 09:00~09:10 (흐름추종)

개장초는 기회 밀도가 종일 대비 2~3배이지만, 구간2 로직으로는 **구조적으로 진입할 수 없다**.
당일고가가 아직 형성되지 않아 이격률이 평균 2.8%(요구 5% 미달)이고, 상대지표(거래강도·체결속도)도
개장초에는 기준선 자체가 높아 서지가 검출되지 않는다. 그래서 **절대 기준** 전용 로직으로 분리했다.

| 구분 | 조건 |
|---|---|
| 진입 | 유효 매수 체결 **≥7회/초** (10초 창, 1·2주 제외, 절대 기준)<br>**AND** 단가 상승 (10초 전 대비)<br>**AND** 순매수비율 ≥0.5 (동일 10초 창) |
| 청산 | **트레일링 2.0%** (보유중 고점 대비) |
| 안전장치 | 손절 1.5% · 최대보유 1800초 · 장마감 청산 · 쿨다운 180초 · 종목당 1일 2회 |

> **매수세는 진입 신호로는 좋고 청산 신호로는 나쁘다.** 체결 서지는 직후 바로 꺾이지만 가격 추세는 더 간다.
> 매수세 소멸로 청산하면 평균보유 68초·평균수익 +2.24%인 반면, 트레일링은 347초·+3.35%다.
> (구간2에서 이미 얻은 교훈의 재확인)

### 구간2 — 09:10 이후 (눌림매매)

매수세가 터지되 **당일고가 대비 눌린 자리**에서만 산다. 이 전략의 실질 엣지는 거래량 서지가 아니라
**할인(평균회귀)** 에 있다 — 16개 지표를 백지에서 경쟁시킨 결과 이격률이 예측력 상위이고
거래량 계열은 약했다(리프트 1.1). 거래량 필터는 알파가 아니라 **노이즈 제거** 역할이다.

| 구분 | 조건 |
|---|---|
| 진입 | 순매수비율 >0.6 · 거래강도 >5.0 · 60초 거래량 ≥10,000주<br>· 체결속도 ≥3.5 · 덩어리배수 ≤30 · **이격률 5~14%** |
| 청산 | 트레일링 2.5% · 본전방어 발동 +1.5% |
| 안전장치 | 손절 1.5% · 최대보유 3600초 · 장마감 청산 · 쿨다운 300초 · 종목당 1일 2회 |

### 종목선정 · 자금관리

- **종목선정**: 감시종목 중 전일 거래대금 ≥50억, 전일 종가 ≥1,000원.
  유동성 필터는 알파 방어선이다 — 6일×100종목 전수 재생에서 탈락군 13건은 합계 **−3.44%**였다.
- **사이징**: 총자산 균등 **3분할**(진입당 총자본의 1/3), 거래당 리스크캡 총자본 1.0%.
  3분할이 위험 대비 수익의 정점이며, 그보다 공격적이면 먼저 온 거래가 자본을 소진해 수익은 안 늘고 위험만 커진다.

## 2. 구성

```
launcher_trader.py       실매매 런처 (수신·저장·매매 3개 워커를 멀티프로세스로 구동)
launcher_analyzer.py     분석 런처 (장 종료 후 일봉수집·백테스팅·종목추천)

trader/
  bot_실시간수신.py        웹소켓 체결틱 수신 + 감시종목 등록
  bot_실시간저장.py        체결틱 CSV 저장 (백테스팅 원천 데이터)
  bot_실시간매매.py        ★ 실매매 판정·주문 (구간1/구간2)
  bot_트레이딩.py

analyzer/
  bot_백테스팅_틱기반매수세.py  ★ 메인 백테스팅 (구간1/구간2, 판정 정의의 기준)
  구간1검증.py              구간1 일일 홀드아웃 누적 검증
  워크포워드검증.py           파라미터 표본 외 검증 (과적합 진단)
  지표탐색.py               제로베이스 지표 예측력 랭킹
  bot_일봉수집.py / bot_종목추천.py / bot_백테스팅_돌파매매*.py

ut/                      공용 (폴더·로그·차트·도구 매니저)
xapi/                    키움 REST/WebSocket API 래퍼
```

## 3. 실행

```bash
python launcher_trader.py      # 장중 실매매 (08:58 기동)
```
```bash
python launcher_analyzer.py    # 장 종료 후 분석
```

백테스팅 파이프라인은 `pick_종목선정 → make_매매정보 → make_거래내역 → make_결과정리 → make_매매일보`
순서로 돌며, **이미 처리한 일자는 건너뛴다**. 로직을 바꾼 뒤 과거분에 소급 적용하려면
`20_매매정보` 이하 산출물을 지우고 재실행해야 한다.

### 검증 도구

```bash
python analyzer/구간1검증.py       # 구간1 홀드아웃 성적 누적 (신규 일자만 자동 평가)
```
```bash
python analyzer/워크포워드검증.py   # 과거 학습 → 다음 미지의 날 검증
```
```bash
python analyzer/지표탐색.py        # 지표 예측력 랭킹 (FEATURE_LIB에 함수 추가 후 --rebuild)
```

## 4. 파라미터

전부 모듈 상단 `_T_*` / `_G1_*` 상수이며 **환경변수로 덮어쓸 수 있다**. 백테스팅과 실매매가 같은 이름·같은 기본값을 쓴다.

| 환경변수 | 기본 | 의미 |
|---|---|---|
| `TB_G1` | `1` | **구간1 킬스위치** — `0`이면 구간1 완전 비활성(기존 동작 정확히 복원) |
| `TB_G1RATE` | `7.0` | 구간1 진입: 초당 매수 체결 횟수 하한 |
| `TB_G1RATIO` | `0.5` | 구간1 진입: 순매수비율 하한 |
| `TB_G1TRAIL` | `2.0` | 구간1 트레일링 % |
| `TB_G1END` | `600` | 구간1 종료 (09:00 기준 초) |
| `TB_RATIO` / `TB_INT` | `0.6` / `5.0` | 구간2 진입: 순매수비율 / 거래강도 |
| `TB_DIST` / `TB_DISTMAX` | `5.0` / `14` | 구간2 진입: 이격률 하한 / 상한 |
| `TB_STOP` / `TB_TRAIL` | `1.5` / `2.5` | 손절 % / 구간2 트레일링 % |
| `TB_DIVISOR` | `3` | 총자산 균등 분할 수 |
| `TB_DEBUG` | – | 진입조건 추적할 종목코드 (콤마 구분) |

원천 데이터와 산출물은 리포지토리 밖 외장 볼륨에 둔다 (`ut/폴더manager.py`가 관리).

## 6. 개발 원칙

이 프로젝트는 과적합으로 여러 번 손실을 본 이력이 있다. 그래서 다음을 규칙으로 삼는다.

1. **표본 외로만 판단한다.** 과거 데이터에 맞춰 파라미터를 고르면 학습셋은 +60%대로 예뻐지지만
   다음 날 성적은 무너진다(검증됨: 튜닝 −12% vs 현행 유지 +9.5%). `워크포워드검증.py`로 확인한 뒤 반영한다.
2. **충실도 게이트를 먼저 통과시킨다.** 검증 도구는 현행 파라미터로 기존 백테 결과를 거래 단위까지
   재현해야 하며, 실패하면 최적화 결과를 아예 출력하지 않는다.
3. **실매매와 백테의 등가를 재생으로 증명한다.** 실제 틱을 실매매 판정 코드에 흘려 넣어
   백테와 진입·청산 시각이 일치하는지 확인한다. (과거에 미배포 코드로 미진입한 장애가 있었다)
4. **하루치 사례로 규칙을 바꾸지 않는다.** 그것이 과적합의 정의다.
5. **새 로직은 킬스위치와 함께 넣는다.**

|---|---|---|---|
| 구간1 | 35건 | 57% | +42.54% |
| 구간2 | 30건 | 70% | +40.96% |
| **계좌** | **65건** | – | **+24.94%** (7일 전부 수익일) |

**구간1은 아직 검증 중인 로직이다.** 표본 외 +31.18%(5폴드 전부 양수)·홀드아웃 1일 +4.67%로 유망하나,
수익의 71%가 상위 3건에서 나오는 팻테일 구조라 큰 움직임이 없는 기간에는 계속 조금씩 잃을 수 있다.
`analyzer/구간1검증.py`로 매일 홀드아웃 성적을 누적하고 있으며, **15거래일 이상 쌓인 뒤 유지 여부를 판단**한다.
이상 징후가 보이면 `TB_G1=0`으로 즉시 되돌린다.
